## 1. 問題：環保局只有一半的資料

台北市行人專用清潔箱從約 2,000 組（113 年 1,956 組）裁到 806 組，只保留 65 處商圈與 63 處景點。
裁撤／復設的流程是：工程處、警分局、交通局、里辦公處會勘 → 填「設置／拆除／遷移評估表」→ 報局核可。
實務上觸發撤除的是兩件事：**桶被家戶垃圾塞爆**、**里長要求**。

這套流程只看得到供給端的「被濫用」，完全沒有需求端的「哪裡需要」。
市民連「這裡原本有桶，現在沒了」都沒有地方講。
我們不是要做智慧垃圾桶，是要把市政決策缺的那一半資料補上。

## 2. 為什麼從遛狗族切入

- 遛狗族是全市最穩定的人肉感測網：每天固定時間、固定路線、必經垃圾桶，而且手上一定有一袋東西要丟。真 IoT 還沒裝之前，他們就是感測器。
- 環保局有「狗便清潔袋箱」open data：有袋可拿，但袋子裝完要丟哪？
  **我們用資料直接算出：124 個狗便袋箱站點裡，98 個（79%）在 100 公尺內沒有行人專用清潔箱。** 這就是「有袋沒桶」。
- 公園狗活動區、河濱是遛狗熱點，但不在環保局保留的「商圈 + 景點」名單裡。

## 3. 解法：找回 → 回報 → 決策

### 3.1 找回
把環保局 open data 的 681 組清潔箱、124 站狗便袋箱畫在地圖上。市民回報「桶還在」「桶消失了」，核准後直接更新桶的狀態；「消失的桶」成為獨立圖層。

> 誠實說明：open data 是「現存」清單，不是裁撤前的 1,900 組。消失的桶只能靠回報累積，這正是需要眾包的原因。

### 3.2 回報（1 分鐘完成）
拍照 → EXIF 自動定位 → 吸附 30 公尺內最近的桶 → 選一個狀況：

| 分類 | 用途 |
|---|---|
| 🗑️ 這裡需要垃圾桶 | 需求訊號（不掛桶） |
| 🤢 桶滿了（50/80/100%） | 清運需求 |
| 👻 桶消失了 / ✅ 桶還在 | 眾包驗證桶位 |
| 🐕 狗便袋箱沒袋了 | 袋箱補給 |
| 🚫 家戶垃圾亂丟 | 撤除風險訊號 |
| ☠️ 毒餌／危險物 | 寵物安全（從 ratdar 延伸） |

同一個桶 24 小時內 2 個不同帳號回報 → 自動升級「多方佐證」。照片經 Claude Vision 審核（寬鬆、fail-open 留人工）。

### 3.3 決策：需求分數與候選復設點
以 ~600m 網格（geohash6）計算：

```
需求分數 = 捷運出站量 + 公車站牌密度 + 狗便袋箱 ×2 + 狗活動區 ×3 + 市民回報（佐證 ×2）− 現存清潔箱 ×2.5
```

單一來源有上限（公車站牌一格最多 4 分），權重全部在 config 可調。輸出三張表，格式對齊環保局既有的評估表，讓資料直接餵進他們的會勘流程，而不是另起一套：

1. **候選復設點 Top 30**：每格附證據明細（哪個捷運站、幾個站牌、幾筆市民回報）+ CSV 匯出。
2. **撤除風險**：家戶垃圾回報集中的格子，建議改加蓋式或加強巡檢，而不是拆。
3. **有袋沒桶**：98 個站點清單。

## 4. 遊戲化（劭筠的點子，收斂版）

核准回報 +10 點、連續天數 streak、行政區皮克敏榜。獎勵提案：**點數換台北市專用垃圾袋**——市府本來就在賣、成本可控、政策上說得通。不做抽獎與虛擬寵物。

## 5. 模擬資料（題目明示可用）

真實滿溢感測資料不存在。Day 2 若有時間，用 seeder 依人流曲線生成「24 組加蓋試辦箱」的模擬滿溢資料，demo「滿了才派車」的動態清運看板。這是 stretch。

## 6. 政策落地路徑

1. 零硬體成本上線，先收 3 個月眾包資料。
2. 用需求分數挑 20 個點復設（優先「有袋沒桶」）。
3. 這 20 個點裝真感測器驗證模型。
4. 全市。資料全部公開 API + CSV。

## 7. 已知限制

- 清潔箱 open data 無歷史版本；消失的桶靠回報。
- 寵物登記無行政區層級 open data；遛狗密度靠 proxy。
- 捷運分時進出量是月檔（每月數百 MB），MVP 先以站點權重 1 計算，可用 `--od` 載入月檔算真實出站量。
- 狗活動區座標為手刻，需現場勘誤。
- 無 PostGIS；geohash + Haversine，幾千筆綽綽有餘。

## 8. 技術

從 hazdar（災害回報）fork：回報 pipeline、Socialite（Google / LINE / LIFF）、Leaflet + 自架 Protomaps、Claude Vision 審核、Filament 後台、bbox + geohash 聚合 API 全部沿用；新增 TrashBin / DemandProxy / DemandCell、匯入指令、需求分數服務、吸附、觀察者、皮克敏榜。217 支自動測試。
