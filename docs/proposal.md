## 1. 問題：環保局只有一半的資料

台北市行人專用清潔箱從約 2,000 組（113 年 1,956 組）裁到 806 組，只保留 65 處商圈與 63 處景點。
裁撤／復設的流程是：工程處、警分局、交通局、里辦公處會勘 → 填「設置／拆除／遷移評估表」→ 報局核可。
實務上觸發撤除的是兩件事：**桶被家戶垃圾塞爆**、**里長要求**。

結果是：**桶留在觀光客去的地方，不在居民每天走的地方。** 用環保局自己的資料就看得出來——
「景點商圈周邊」清單就有 687 組；逐點清單的 733 組裡，46% 在景點商圈 500 公尺內。
以「每個狗便袋箱分到幾組清潔箱」看各區：中正區 8.9、大安區 6.5，南港區只有 0.6、內湖區 1.2，**相差近 15 倍**。
（數字取自 2026-10-23 的官方資料；桶位每天自動同步，最新值見網站「數據判讀」頁。）

隔壁的新北市走得更遠：道路沿線垃圾桶已全面取消，只剩觀光區由各管理單位自行設置的 455 個
（[自由時報 2025-08-02](https://news.ltn.com.tw/news/life/breakingnews/5130280)）。撤桶的理由都是「被濫用」，沒有人問過「哪裡需要」。

這套流程只看得到供給端的「被濫用」，完全沒有需求端的「哪裡需要」。
市民連「這裡原本有桶，現在沒了」都沒有地方講。
我們不是要做智慧垃圾桶，是要把市政決策缺的那一半資料補上。

## 2. 為什麼從遛狗族切入

- 遛狗族是全市最穩定的人肉感測網：每天固定時間、固定路線、必經垃圾桶，而且手上一定有一袋東西要丟。真 IoT 還沒裝之前，他們就是感測器。
- 環保局有「狗便清潔袋箱」open data：有袋可拿，但袋子裝完要丟哪？
  **我們用資料直接算出：468 個狗便清潔袋箱裡，267 個（57%）在 100 公尺內沒有行人專用清潔箱。** 這就是「有袋沒桶」——市府發了袋子，卻沒地方丟。
- 公園狗活動區、河濱是遛狗熱點，但不在環保局保留的「商圈 + 景點」名單裡：468 個狗便袋箱只有 43% 在 100 公尺內找得到清潔箱。
- 反對加桶的人最常說「把垃圾帶回家」——對遛狗族來說，這代表每次都得提著一袋狗便走完整趟散步。附近沒桶時，他們現在就是只好這樣做；這是最明確、也最該被看見的需求。

## 3. 解法：找回 → 回報 → 決策

### 3.1 找回
把環保局 open data 的 733 組清潔箱（另有景點商圈周邊 95 處、687 組）、468 個狗便清潔袋箱畫在地圖上，每天凌晨自動與官方清單同步。市民回報「桶還在」「桶消失了」，核准後直接更新桶的狀態；「消失的桶」成為獨立圖層。

> 誠實說明：open data 是「現存」清單，不是裁撤前的 1,900 組。消失的桶只能靠回報累積，這正是需要眾包的原因。

### 3.2 回報（1 分鐘完成）
拍照 → EXIF 自動定位 → 吸附 30 公尺內最近的桶 → 選一個狀況：

| 分類 | 用途 |
|---|---|
| 🗑️ 這裡需要垃圾桶 | 需求訊號（不掛桶） |
| 🤢 桶滿了（50/80/100%） | 清運需求 |
| 👻 桶消失了 / ✅ 桶還在 | 眾包驗證桶位 |
| 🐕 狗便袋箱沒袋了 | 袋箱補給 |
| 🚫 家戶垃圾亂丟 | 撤除風險訊號 |
| ☠️ 毒餌／危險物 | 寵物安全（從 ratdar 延伸） |

同一個桶 24 小時內 2 個不同帳號回報 → 自動升級「多方佐證」。照片經 Claude Vision 審核（寬鬆、fail-open 留人工）。

### 3.3 決策：需求分數與候選復設點
以 150m 方格計算，每格看「格中心附近」的訊號（越近越重），不看訊號剛好落在哪一格——隔壁馬路的站牌和桶照樣算進來：

```
需求訊號 = 捷運出口人流 + 公車站牌 + 遛狗地點 ×2 + 狗活動區 ×3 + 市民回報（佐證 ×2）     ← 300m 內線性衰減
需求分數 = 需求訊號 ×（1 + 缺桶加成）− 附近現存清潔箱 ×2.5（300m 內線性衰減）
```

- **捷運出口人流**：390 個出入口，每站權重 = √(月出站量 ÷ 台北車站出站量) × 8，平分給該站各出口。站內垃圾桶在進站閘門旁，出站往外走的人找不到桶也不會回頭丟，所以出口正上方不加權、100m 處最高、500m 外淡掉。
- **缺桶加成**：格中心到最近清潔箱 300m 內為 0，1000m 以上為 1（中間線性）——人多又離桶遠的地方需求加倍。用乘的不用加的：山區零星站牌離桶再遠，訊號弱就還是弱，不會擠上榜。
- 例：南港區理想公園一格，遛狗地點（狗便袋箱）2.6 + 公車 2.5 = 5.1，最近清潔箱 1.7km、缺桶加成滿額 → 需求分數 10.3（全市第一）。

單一來源有上限（公車站牌最多 4 分、捷運最多 10 分），權重與距離門檻全部在 config 可調。候選清單 300m 內只取最高的一格，前 30 名就是 30 個不同地點。輸出三張表，格式對齊環保局既有的評估表，讓資料直接餵進他們的會勘流程，而不是另起一套：

1. **候選復設點 Top 30**：每格附證據明細（哪個捷運站、幾個站牌、幾筆市民回報）+ CSV 匯出。
2. **撤除風險**：家戶垃圾回報集中的格子，建議改加蓋式或加強巡檢，而不是拆。
3. **有袋沒桶**：267 個袋箱清單。

### 3.4 為什麼這樣算：每個設計都對應一個真實行為

一張需求圖好不好用，要看它在「該紅的地方紅、不該紅的地方不紅」。我們每個設計都從使用者的實際行為出發，並用資料驗證過：

| 真實行為 | 錯誤做法會發生什麼 | 我們的做法 |
|---|---|---|
| 人找垃圾桶看的是**走幾步路**，不看行政或網格邊界 | 傳統分格只數「格子裡有幾個」：桶就在隔一條馬路的對面，卻因為落在另一格而被判定「這區沒桶」 | 每 150m 一格，但看的是**格中心 300m 內**的站牌、桶與回報，越近影響越大。格線只是用來顯示，不影響判斷 |
| 捷運站內的垃圾桶在**進站閘門旁**（站內禁止飲食）；出站後往外走的人找不到桶，**不會回頭進站丟** | 把需求放在站點正上方，結果建議在已經有站內桶的地方設桶 | 從 390 個出入口往外算：出口旁不加權，往外 100m 最高，500m 外淡掉，需求落在**出站動線**上 |
| 缺桶的地方是**人多又離桶遠**，不是單純離桶遠 | 只看「離桶多遠」的話，山區最遠，卻最不需要 | 缺桶加成是**乘在人流訊號上**：有人才放大，山區零星站牌再遠也還是弱訊號 |
| 一個熱點會影響周邊好幾格 | 候選前 30 名被同一個熱點的相鄰格子佔滿 | 300m 內只取最高的一格，前 30 名就是 **30 個不同地點** |
| 同一個公園常裝一整排狗便袋箱 | 袋箱裝得多的公園被灌成第一名，擠掉其他缺桶地點 | 150m 內的袋箱算**同一個遛狗地點**，只計一次 |
| 反對加桶的理由：桶會變成家戶垃圾的新髒亂點、應該鼓勵把垃圾帶回家 | 全面加桶確實會重演「被濫用 → 撤桶」的循環 | **不全面加桶**：只挑「狗便袋已在手上、附近沒桶」的點；「撤除風險」圖層追蹤家戶垃圾回報，集中處建議改加蓋式或加強巡檢；先 20 點試辦、裝感測器驗證再擴大 |
| 新北市街頭已全面撤除行人清潔箱，只剩捷運站內的桶 | 新北只有捷運資料（沒有公車、袋箱），排名時新埔、板橋會因資料不對等擠進前幾名 | 地圖**照畫新北**（缺桶是事實，也是「全面撤桶後」的對照組），但候選排行**只排臺北市** |

**驗證結果**（舊版＝1.1km 格子、只數格內）：

- 山區不再誤判為熱區：竹子湖 8.0 → 2.0、指南宮 2.9 → 0.8、貓空 0.1。
- 前 10 名全部是公園與狗活動區、離最近清潔箱 400m–3km（南港理想公園、北投泉源公園、山水綠生態公園、文山萬興狗活動區…）——正是遛狗族天天去、卻找不到垃圾桶的地方。
- 每一格都能回答「為什麼」：地圖上點任一格，就列出分數組成（哪些捷運出口、幾個站牌、最近清潔箱幾公尺、附近哪些桶扣了分）。評審與環保局可以逐格檢查，不是黑盒子。
- 所有權重與距離門檻都在設定檔中，數值可公開討論、可依會勘結果調整，全市重算只要 2 秒。

## 4. 遊戲化（劭筠的點子，收斂版）

核准回報 +10 點、連續天數 streak、行政區巡桶英雄榜。獎勵提案：**點數換台北市專用垃圾袋**——市府本來就在賣、成本可控、政策上說得通。不做抽獎與虛擬寵物。

## 6. 政策落地路徑

1. 零硬體成本上線，先收 3 個月眾包資料。
2. 用需求分數挑 20 個點復設（優先「有袋沒桶」）。
3. 這 20 個點裝真感測器驗證模型。
4. 全市。資料全部公開 API + CSV。

## 7. 已知限制

- 清潔箱 open data 無歷史版本：已裁撤的桶只能靠回報。上線後每天同步官方清單，之後被移除的桶會自動標記並記下移除日期。
- 環保局「景點商圈周邊清潔箱」一筆是一個地點（備註 N 處），以單點計，離逐點清單 100m 內者視為同一批桶。
- 公車站牌、狗便袋箱資料只有臺北市：新北的格子只反映捷運人流，地圖照畫但不列入候選排行與行政區統計。
- 寵物登記無行政區層級 open data；遛狗密度靠 proxy。
- 捷運權重取自 2026-08 月 OD 出站量（月檔約 300MB，換月需重算）；環狀線 10 站 OD 無資料，暫以中位數計。
- 狗活動區座標為手刻，需現場勘誤。
- 公車站牌 SHP 的站名欄只有 22 bytes，535 個站名被截斷；已用臺北市公車動態資訊（GetStop）比對站位編號與位置找回 452 個全名，其餘 83 個去除殘字。
- 無 PostGIS；需求分數用固定原點方格＋平面距離（台北範圍誤差 <0.1%），全市 9,400 格重算約 2 秒。
